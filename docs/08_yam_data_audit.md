# 真实采集数据审计报告

审计日期：2026-11-15。统计来自当前工作区现存文件的实际读取；配置值只用于解释，不用于推算数据量。组名S01–S10和Episode键已匿名化，任务原始ID与采集者目录映射只保留在本地审计附录。

## 1. 范围、方法与覆盖

完整按物理文件顺序解码 **3,400个MCAP**，启用reader CRC校验；读取 **3,402个关联MP4** 的容器元数据。按每组字典序首个Episode完整解码 **12个视频、9,635帧**，不是随机抽样，也没有完整解码其余3,390个视频。额外14个camera-test视频只查容器头，单独列出。原数据、元数据及日志均未被改写。

公开包的原始统计脚本为`scripts/audit_dataset.py`，补充视频头审计为`scripts/audit_extra_videos.py`，日志统计为`scripts/audit_runtime_logs.py`。Markdown/匿名表格生成器保留在原工作区的docs/audit/tools中；公开统计可由原始脚本的JSON/CSV复核。完整逐Episode、逐视频、逐Topic和逐维结果分别见本章末尾CSV。

频率=总Episode内相邻间隔数/这些间隔之和；不跨Episode拼接等待时间。中位频率=1000/中位log间隔(ms)，P95和抖动标准差来自实际间隔。机器人主表用MCAP log time，另表单独检查source Header；相机log/publish/Header相等。所有统计均包括现有文件保留的ARMING样本；不等同于UI纯Recording时长。

## 9. 运行日志、队列与历史删除账本

只读扫描56份runtime JSONL，共1,010,563行。左腕超时错误状态出现87条快照，右腕出现118,953条；按每文件错误状态变化各观察到1次进入该状态，均在idle且episode_id为空。状态会持续保留，**119,040条错误快照不能解释为119,040次独立事故**。根因和恢复闭环未见完整证据，详见09。

日志保留的编码器高水位：max_pipe_write_ms=451.593819ms、max_queue_depth=10；软件dropped_frames峰值为0。采样到的即时queue_depth最高1不等于真实队列从未超过1，高水位字段保留了更长观察窗。软件零丢弃不否定设备帧号缺口。未记录最终落盘时间，不能量化完整写入延迟。

7份删除账本合计166条：validation_failed 37条/441.265s，user_deleted 129条/929.611s。该时长来自业务账本，通常为UI录制时间口径；账本功能引入前的删除未知，不能据此计算整个历史采集失败率，也不能重建已删除的数据。它们不计入现存3,400个Episode及总时长。

## 10. 已确认质量问题与无法统计项

| 事项 | 本次结论 |
| --- | --- |
| 任务标签 | 全部单臂仍为smoke ID，真实语义任务统计待整理 |
| 源帧连续性 | 1,414个设备帧号缺失；分层根因待确认 |
| 机器人源新鲜度 | 13,259个重复Header；底层CAN测量年龄未保存 |
| 严格60Hz验收 | 部分50ms间隔不符合35ms strict；本报告未批量运行正式validator，不声明全文件正式pass |
| 真实动作 | 没有CAN目标命令流/同步开关，Leader输入不能一律视为执行动作 |
| 物理同步 | 无曝光/每电机硬件时间戳，不能报告真实同时采样误差 |
| 源样本丢失 | 无保存的原始telemetry sequence，缺失样本数及控制发送率不可精确计算 |
| 视频完整性 | 全量头检查+确定性12视频解码；非全部像素流验证 |
| 历史失败 | 仅保留删除账本与部分运行状态；不能推断全历史失败率/已删除文件内容 |
